## Ordre conseillé

1. **`understand-project-structure` d’abord** pour recadrer le projet actif, les specs partagées, les kinds/relations/tags et les vues déjà présentes.
2. **Revalider le C1**, même rapidement : frontière du système, acteurs, externes.
3. **Concevoir ensuite le C2** : containers runtime, relations utiles, portée de la nouvelle vue.
4. **Déléguer le détail** à des skills spécialisés : `create-element`, `create-relationship`, `design-view`, puis `test-model` avant clôture.
