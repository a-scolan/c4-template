Do not put everything into one shared bucket. The current shared files already point to a sensible split: keep technical conventions together in shared specifications, because that is where reusable element kinds, tags, colors, and relationships belong. Reusable business models should be separated from those specs, but kept shallow and simple so the repo does not turn into a maze. A practical structure is: one shared specs area for technical conventions, one small shared domain area for canonical actors and systems that several projects truly reuse, and per-project model and view files for everything project-specific. That gives you reuse without mixing DSL conventions and business domain content in the same files.
