Do not put everything in the shared area. Separate technical conventions from reusable domain models, but keep the split small and intentional so the repository stays easy to navigate. Put technical conventions in projects/shared, such as shared spec files, tags, relationship types, styles, and shared images. If some business models are genuinely reused across multiple projects, place them in a small dedicated common-domain or externals project, or in a clearly scoped shared model file for cross-project externals, rather than mixing them into the technical specs. Keep project-specific systems, containers, and actors inside their owning project.
