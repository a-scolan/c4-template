Not in the shared specifications files. The readable shared files define reusable specifications: element kinds like Actor_Person, System_New, and Container_Api, plus shared tags, colors, and relationship types. That makes projects/shared/ a good place for modeling conventions, not for concrete business instances such as paymentsCore or backOfficeUser. If those two are truly canonical concepts reused by multiple projects, place them in a separate shared business-model layer and let each project reference that canonical definition. If they belong only to payments, keep them inside the payments project. Cross-project references should point to shared canonical business elements when they exist; project-local containers, components, and views should remain local.
