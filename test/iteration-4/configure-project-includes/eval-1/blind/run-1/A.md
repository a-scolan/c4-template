Split progressively, not all at once. Start from the visible baseline layout and separate model from views first: put elements and relationships in `system-model.c4`, and keep initial views in `system-views.c4`. Then split views by concern as they stabilize: `context-views.c4` for C1, `container-views.c4` for C2 view definitions, and `component-views.c4` for C3 view definitions. If the model side is still crowded, split it further like the visible showcase layout: `actors-systems.c4` for top-level actors/systems, `containers.c4` for container model parts, and `components.c4` for component model parts. Put Use Cases in a dedicated `use-cases.c4`, deployment in `deployment.c4`, and operational/monitoring content in `operations.c4` rather than mixing them into C1/C2/C3 view files.
