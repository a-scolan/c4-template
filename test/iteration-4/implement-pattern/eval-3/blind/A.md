Model Stripe with two distinct interactions. First, your internal Container_Api calls the external Stripe system to create the payment over HTTPS. Second, model a separate async relationship from Stripe back to your internal webhook-receiving endpoint over HTTPS. If the webhook lands in the same API, it helps to show a dedicated internal component or endpoint for that receiver so the second leg is visibly separate. Avoid a reverse calls arrow that looks like the synchronous response to the create-payment request; the webhook is a later, independent event.
