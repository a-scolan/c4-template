Yes. This is exactly the kind of decision that should be captured in an ADR. A solid frame would be: title such as ADR/NNNN-choose-postgresql-for-primary-transactional-store; status Proposed or Accepted; context covering transactional guarantees, relational querying, backup and restore, and the comparison with MongoDB; decision stating PostgreSQL is the primary database container for the main transactional workload; impacted elements covering the API or backend, main database container, workers or services depending on core persistence, and any persistence or failover views already defined; alternatives considered such as MongoDB for schema flexibility; consequences with positives, negatives, and operational follow-up; and next steps to update the model and documentation. Use real element IDs or stable names and include both benefits and costs so the ADR reads as rationale rather than advocacy.
