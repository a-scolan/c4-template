Do not jump straight into C3. Because you are resuming a multi-project workspace after shared-spec changes, start with understand-project-structure to confirm the current rules, valid kinds, relationships, and view organization. Then re-check that the existing C1 and C2 are still coherent under the updated shared specs; if the structural base moved, fix that first. Next, decide whether the target container truly deserves a C3 view; add it only if the container is central, sensitive, risky, or complex enough that C2 is no longer sufficient. For the C3 work itself, hand off to create-element for components, create-relationship for their typed connections, and design-view for the static C3 view. Once that structural detail is stable, document the nominal user scenario with create-sequence-view. Finish with test-model.
