Start top-down. If the workspace rules are not already clear, begin with understand-project-structure. Then do C1 first to define the system boundary, actors, and external systems. Next do C2 to identify the runtime or deployable containers and the relationships that explain how the system works. Only then add C3, and only for containers that are central, risky, or internally complex enough that C2 is no longer explanatory. After the structural model is stable, add dynamic views for time-ordered workflows and deployment views when runtime topology matters. Finish by validating with test-model.
