Follow the structural levels in order. 1) Start with C1 context: identify actors, your SaaS product as a system, and external systems, then add the high-level relationships. 2) Move to C2 containers: decompose your system into containers such as web app, API, database, queue, and storage, and model their relationships. 3) Add C3 components only for containers whose internal building blocks matter. 4) Add deployment only when you need runtime or infrastructure topology. The usual backbone is C1 then C2; C3 is optional, deployment is optional, and sequence/scenario-style views are optional and should be added only when you need time-ordered behavior.
