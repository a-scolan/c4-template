First learn the local semantic conventions, not UML habits: C1 uses Actor and System kinds, C2 uses typed containers such as Container_Api, Container_Queue, and Container_Database, and C3 uses Component. The real sources of truth are the shared spec files and the shared cheat sheet. Skill files give workflow guidance only, and example projects are references, not taxonomy. Also lock in the core model relationships uses, calls, async, reads, and writes, plus repo tags such as Internal, External, Queue, Production, and Vm. After preflight, hand off to the next task-specific skill, usually c4-modeling-process.
