Usually no. The shared cheat sheet says to put interaction technology on the system-model relationship, and to add a port only when it is non-default for the protocol. It also says deployment relationships are for infrastructure-specific connections, while normal application traffic should usually be inherited in deployment through instanceOf. So webApp -> apiApp and apiApp -> dbApp should normally live in the logical model, using the relationship type that matches the behavior there. For the database side, prefer the logical relationship that expresses the behavior, such as reads or writes, and attach the technology there. Keep deployment.c4 for deployment-only edges like firewall hops, monitoring scrapes, backup mounts, or other infrastructure links.
