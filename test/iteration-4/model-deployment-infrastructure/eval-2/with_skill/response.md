Do not invent worker VMs or host specs you do not actually know. The shared deployment spec includes Node_Cluster, so the honest managed-Kubernetes shape is: a production environment, a truthful platform zone, a Node_Cluster for the managed Kubernetes runtime, and Node_App instances under that cluster, each linked with instanceOf. If MongoDB runs outside the cluster, place it under its own honest infrastructure node in the appropriate zone; if it is a managed external service, model it as such rather than pretending it sits on a VM you control. The key is to model the platform boundary you actually know, not fake physical hosts.
