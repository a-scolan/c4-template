Keep readability by separating tier structure from cross-cutting and site-level concerns. For audit or security, add a sibling internal zone under the same production environment, treated as shared internal infrastructure rather than squeezing it inside #Dmz, #AppTier, or #DataTier. Tag it with #SharedInfra and, if useful in your taxonomy, a security-oriented tag; connect it only where needed for logs, audit events, policy checks, identity, or security telemetry. For disaster recovery, model a second site above the tier level: a sibling Node_Datacenter or standby production environment with its own local tiers. Tag the standby site with #Recovery and #Backup semantics and draw only the essential primary-to-standby links, especially data replication and configuration or artifact sync. That way each site remains readable as a clean tier stack, while cross-cutting and DR concerns sit beside or above the tiers instead of cluttering them.
