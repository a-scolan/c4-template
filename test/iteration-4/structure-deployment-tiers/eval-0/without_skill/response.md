For production, model one Node_Environment tagged #Production and split it into four zones: #Dmz for the API gateway only, #AppTier for business services, #ProcTier for RabbitMQ plus the async worker, and #DataTier for MongoDB plus MinIO. This keeps the async path readable: AppTier publishes work, ProcTier buffers and executes it, DataTier stores results. Responsibilities: #Dmz handles HTTPS ingress, TLS termination, routing, rate limiting, and request filtering; #AppTier handles business logic, auth enforcement, orchestration, and job publishing; #ProcTier handles AMQP queueing and background document processing; #DataTier handles durable metadata and object storage. Place monitoring in a sibling internal zone tagged like shared monitoring or observability infrastructure, not in #Dmz. Network rules: Internet -> #Dmz on HTTPS only; #Dmz -> #AppTier on the minimum internal service ports only; #AppTier -> #ProcTier on AMQP or TCP and any tightly scoped control path; #AppTier and #ProcTier -> #DataTier only on required database and object-storage ports; no direct #Dmz -> #DataTier; no Internet -> #AppTier, #ProcTier, or #DataTier; and no broad east-west traffic between tiers unless there is a clear operational need. Monitoring should receive telemetry from internal tiers, or poll exporters, but it should remain non-public.
