Use this pre-commit checklist: 1) Kinds: confirm the new worker uses a container kind that exists in `projects/shared/spec-containers.c4`; for a background processor, sanity-check whether `Container_ProcessingServer` or `Container_Webapp` better matches its role. 2) FQNs: trace every reference to the worker in model, views, and any `instanceOf`-style usages and make sure the same system-qualified path is used everywhere; the shared examples use container FQNs like `vault.api`, so your worker should follow one consistent pattern with no stale names. 3) Relationships: verify each edge uses a shared relationship from `projects/shared/spec-global.c4` (`calls`, `async`, `reads`, `writes`, `uses`) and that the label plus technology still match the behavior; `SPEC_CHEATSHEET.md` says to keep the interaction technology on the system-model relationship. 4) View scope: in the dedicated C2 view, only the relevant actor and `#Container` elements should appear; if anything rendered as a `#Component`, the scope is wrong for C2. 5) Rendering: render the view and check that the worker shows the expected icon/shape for its kind, synchronous links stay solid blue, async links stay dashed blue, and there are no orphaned, duplicated, or unexpectedly inherited elements.
