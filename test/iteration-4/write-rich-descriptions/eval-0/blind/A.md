Use an element-creation step first, because rich descriptions are a follow-up step after the element exists. For the processing service, create the service or container first, then use a normal system-model description: short prose by default, with a sparse metadata block only if you truly need queryable fields such as owner or regions. For the production VM, create the deployment node first, then use a markdown table inside the description as the primary format, with network interfaces first; add deployment metadata only if automation will query IP, OS, RTO, or similar fields.
