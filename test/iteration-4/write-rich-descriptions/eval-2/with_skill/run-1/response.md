Keep it to a single table and make it scan-friendly. Put eth0 and eth1 first, then OS, then hardware such as CPU, RAM, GPU, and Disk if they matter for capacity or troubleshooting, then only the operational rows that drive action on call, such as runtime, health check, RTO, and maybe RPO. Do not dump every implementation detail into the block; if a value does not help an operator diagnose, route, recover, or automate, leave it out. Also do not repeat hostname, gateway, relationships, or tags. If automation needs the same data for inventory, compliance, or capacity planning, duplicate only those key fields into metadata; otherwise skip metadata entirely.
