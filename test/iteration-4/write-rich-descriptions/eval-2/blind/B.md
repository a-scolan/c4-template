Write a compact operator narrative, not a hardware inventory. A good pattern is: one summary sentence for the VM's role; one sentence for interface purpose (`eth0` for application traffic, `eth1` for management or monitoring, if that is the case); one sentence for capacity that actually affects troubleshooting or sizing (CPU/RAM/GPU only if it matters); one sentence for the operational contract (monitoring, alerts, backup, patching, owner); and one sentence for unusual constraints or risk. Keep only details that change decisions during incident response or maintenance. Avoid listing every metric, threshold, package, or low-value hardware fact. If the GPU is not operationally important for this API VM, omit it; if it is, state why it matters.
