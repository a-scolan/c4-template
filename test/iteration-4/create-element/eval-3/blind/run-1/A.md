Do not create two new kinds. Kinds here describe reusable categories, and mock vs prod is usually not a category. If both matter in the architecture, create two elements and reuse existing kinds that fit each one. For example, the real payment provider can be an external system, while the mock can be another external system or an internal API container depending on where it runs. Handle the mock-vs-prod difference with the element names, descriptions, tags, and views; that is element modeling plus view design, not kind creation.
