No. In this workspace, kinds are shared reusable categories such as Container_Api, Container_Webapp, and Container_ProcessingServer, not one-off business services. Container_UploadOrchestrator would encode a single service name as a kind, which is the wrong level of abstraction. Before adding any new kind, first check the existing shared container kinds and use the closest fit. Only add a new kind if no current kind fits and the new kind represents a recurring category that belongs in the shared specification, not just one element in one model.
