Use four primary deployment tiers. `#Dmz`: API gateway/edge ingress only; TLS termination, routing, WAF/rate limiting; inbound allowed from the Internet, outbound allowed only to `#AppTier`, and no direct access to data stores. `#AppTier`: business services and synchronous APIs; authentication, validation, orchestration, document workflow decisions; accepts traffic only from `#Dmz` or trusted internal callers, may publish to RabbitMQ, and may access approved data services. `#ProcTier`: async worker(s) and, if it is dedicated to this processing flow, RabbitMQ; queueing, retries, document conversion/OCR/indexing, background jobs; no public ingress, accepts messages from `#AppTier`, and can write results to `#DataTier`. `#DataTier`: MongoDB and MinIO; durable metadata/content storage, backup/restore, replication; private inbound only from `#AppTier` and `#ProcTier` on required ports, never from `#Dmz`. Monitoring is usually cleaner as a sibling shared observability zone or a separate focused view because it is cross-cutting rather than a core business tier.
