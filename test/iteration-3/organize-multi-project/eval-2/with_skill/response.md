This skill is enough for the workspace-structure decision: how to add the project, where it lives, and what the minimum project shape should be. For the actual `include.paths` and `imageAliases` details, combine it with `configure-project-includes` - that is the handoff called out by this skill. Either way, each project still owns its own `likec4.config.json`, and the shared include should stay relative as [`../shared`]; in this repo, `projects/template/likec4.config.json` is the local baseline.
