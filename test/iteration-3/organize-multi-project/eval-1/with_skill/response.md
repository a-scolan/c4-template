Not a good idea. `projects/shared/` should contain reusable definitions only - specs, tags, relationship types, and shared assets - not project-specific models like `paymentsCore` or `backOfficeUser`. Keep those elements in the owning project, for example `projects/payments/`. If something is truly shared across projects, model it explicitly as a shared external reference or give it its own small `projects/externals/`-style project. Keep cross-project references explicit and minimal, and do not create project-to-project circular dependencies.
