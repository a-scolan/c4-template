Usually not in the current shared specifications area. In this workspace, `projects/shared/spec-*.c4` is clearly used for reusable specification assets such as element kinds, tags, relationship types, colors, and icons. Putting concrete business instances like `paymentsCore` and `backOfficeUser` into those spec files would mix conventions with domain content. Better rule: if they are mainly for the payments project, keep them in `projects/payments/system-model.c4`; if they are truly canonical across several projects, promote them into a separate shared model area such as `projects/shared/domain/` or `projects/shared/common-models/`, not into the spec files themselves. Cross-project references should use one canonical definition only: include the shared domain model from consuming projects, and avoid project-to-project include chains when possible. If another project needs a formerly local element, extract it once to shared instead of duplicating it.
