Do not put everything in `projects/shared/`. Keep `projects/shared/` for truly reusable specs, conventions, tags, relationship definitions, and shared images. Put reusable business models in a small dedicated domain project instead of the shared spec area - for example `projects/common-business/` or `projects/payments-domain/` with its own `likec4.config.json`, model file, and views file. That keeps the structure simple: shared conventions in one place, owned domain models in another, and project-specific systems in their own folders. Keep dependencies one-way and explicit to avoid circular project links; if you need help tuning `include.paths` or `imageAliases` for that setup, use `configure-project-includes`.
