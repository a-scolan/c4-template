Do not dump everything into one shared bucket. The clean approach is to separate the concerns, but keep the structure shallow: keep `projects/shared/spec-*.c4` for technical conventions and reusable DSL/spec definitions, keep `projects/shared/images/` for common icons/assets, add a small `projects/shared/domain/` (or similarly named folder) for reusable business actors, systems, and relationships that genuinely belong to multiple projects, and keep `projects/<project>/` for project-specific models and views. That avoids a maze while still giving you a clear split between shared technical specs and shared business models. Good rule of thumb: if an element would still exist even if one project were deleted, it may belong in shared domain; if it mainly describes one bounded context, keep it local to that project.
