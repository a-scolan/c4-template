Do not create two new kinds. Reuse existing kinds and model two elements only if both variants are architecturally relevant; otherwise keep only the production dependency in the main system model and leave the mock as test-only detail. For example, a real payment provider can be `System_External`, and the mock can be another `System_External` or an internal `Container_Api`, depending on where it lives. Use `implement-pattern` for the mock-vs-prod distinction, and `create-element` for the element declarations themselves.
