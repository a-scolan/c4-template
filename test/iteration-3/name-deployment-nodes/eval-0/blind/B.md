Use the repo’s deployment style: short environment name at the parent level, then simple child ids. A consistent set would be: Environment: `Prod` (display name `Production`). Zones: `Dmz`, `AppTier`, `ProcTier`, `DataTier`, `OpsTier`. VMs: `apiGatewayVm`, `uploadVm`, `workerVm`, `mongoVm`, `monitoringVm`. Fixes: `ProdApiVM` -> `apiGatewayVm` (or `ProdApiGatewayVm` only if you need a flat global id), `prod_upload_vm` -> `uploadVm`, `AppServers` -> `AppTier`, `MonitoringTier` -> `OpsTier` (or `Monitoring` if you want a service-specific zone name instead of a tier name). The cleanup rules are: no underscores, use `Vm` not `VM`, avoid plurals for a single zone, and do not repeat `Prod` in every child name when the parent environment is already `Prod`.
