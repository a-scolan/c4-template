Between the two flat options, prefer `ProdEuApiVm`, not `EuProdApiVm`, because it keeps one broad-to-specific order: `Environment + Region + Role + Kind`. That said, in this repo’s nested deployment style the cleaner answer is: neither. Put the environment at the parent level as `Prod`, then use region/tier zones such as `EuAppTier`, `EuDataTier`, `UsAppTier`, `UsDataTier`, and VM ids such as `euApiVm`, `euWorkerVm`, `euMongoVm`, `usApiVm`, `usWorkerVm`, `usMongoVm`. To keep everything readable, apply one convention everywhere: same token order, PascalCase for deployment node kinds, lower-camel ids for instances, `Vm` not `VM`, and stable region tokens such as `Eu` and `Us`.
