Order: 1) call `understand-project-structure` first to find the target project, its `likec4.config.json`, shared includes, and existing conventions; 2) inspect the current model and existing C1/C2 views; 3) define the exact audience and scope of the new C2 view; 4) if you need to confirm allowed shared kinds/tags, call `lookup-element-kinds`; 5) if required containers or external systems are missing, call `create-element`; 6) if required flows are missing, call `create-relationship`; 7) build the new view with `design-view`; 8) refine filters, layout, focus, and drill-down with `customize-view`; 9) improve weak descriptions with `write-rich-descriptions` if needed; 10) validate with `test-model` and use `troubleshoot-errors` if the model complains; 11) record important trade-offs with `document-decision` when the view captures an architectural choice. If shared specs look stale, insert `sync-with-template` before step 2.
