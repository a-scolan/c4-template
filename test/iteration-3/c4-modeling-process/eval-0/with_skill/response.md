Follow a top-down process: start with C1 to define the system boundary, actors, and external systems; then move to C2 to identify the runtime or deployable containers and their interactions; then add C3 only for containers that are complex, risky, or central enough to need internal detail. Add Dynamic views and Deployment views only after the structural model is stable, and treat both as optional and targeted rather than mandatory. Do not start bottom-up from classes, folders, or frameworks.
