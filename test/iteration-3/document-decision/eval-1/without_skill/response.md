Usually no. A GitHub Actions workflow change by itself is normally implementation or operational configuration, not an architecture decision record. I would write an ADR only if the workflow change captures a durable, high-impact decision about system delivery architecture or engineering governance — for example adopting a new release promotion model, mandatory signed builds, a monorepo CI architecture, or a compliance-driven deployment approval design. Otherwise, document it in the pull request, repository docs, or operational runbook instead.
