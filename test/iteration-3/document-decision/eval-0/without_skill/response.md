Yes — this is a strong ADR candidate because it changes a foundational architecture choice for the main database container. Using the template in `projects/template/ADR/0000-template.md`, frame it like this: Title: Use PostgreSQL as the primary operational database instead of MongoDB. Status: Proposed. Context: the main workload needs reliable transactions, strong consistency, relational queries, reporting, and clear data constraints; the team likely benefits from mature SQL tooling, backups, migrations, and operational familiarity; MongoDB remains an alternative but is less aligned if the core model is relational and integrity-heavy. Decision: choose PostgreSQL for the main database container; model core domain data relationally; use migrations and constraints explicitly; use document-style fields only where justified rather than making MongoDB the primary store. Consequences — Positive: ACID transactions, better joins and reporting, stronger data integrity, mature ecosystem, easier governance. Negative: less flexibility for highly variable documents, more schema discipline, migration overhead. Neutral: document storage can still be introduced later for a bounded use case if needed. Notes: list alternatives considered such as MongoDB as primary and polyglot persistence from day one, plus evidence such as query patterns, consistency requirements, and recovery expectations.
