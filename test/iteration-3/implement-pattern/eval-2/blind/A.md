Model Redis as a separate cache container in front of, but not instead of, Postgres. A consistent choice here is `redisCache = Container_DataServer 'Redis Cache' { technology 'Redis' }` plus `postgres = Container_Database 'Postgres' { technology 'PostgreSQL' }`, with the API talking to both: `api -[reads]-> redisCache 'Reads cached data'`, `api -[reads]-> postgres 'Reads on cache miss / source of truth'`, `api -[writes]-> postgres 'Persists data'`, and optionally `api -[writes]-> redisCache 'Warms or invalidates cache'`. What keeps the meaning clear is leaving Postgres explicitly in the model as the source of truth and not drawing Redis as the only data target. Also avoid inventing a `Redis -> Postgres` sync arrow unless that replication actually exists.
