Model Stripe as a request/callback pattern with two separate one-way relationships: `paymentsApi = Container_Api 'Payments API'`, `stripe = System_External 'Stripe'`, then `paymentsApi -[calls]-> stripe 'Creates payment' { technology 'HTTPS' }` and separately `stripe -[calls]-> paymentsApi` (or a dedicated webhook handler component/endpoint) `'Sends payment confirmation webhook' { technology 'HTTPS' }`. If you want more detail inside the API, the inbound endpoint can be a `Component` such as `Stripe Webhook Handler`. The key is not to draw the webhook as a return from the first call and not to collapse both steps into one bidirectional line; they are two distinct HTTP calls with different initiators, so the overall business flow is asynchronous even though each hop is modeled as `calls`/`HTTPS`.
