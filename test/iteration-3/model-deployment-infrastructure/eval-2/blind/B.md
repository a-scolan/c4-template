Do not invent VMs or physical hosts that you cannot actually observe. In managed Kubernetes, keep the hierarchy honest by starting with the concrete deployment boundary you do know: `Node_Environment Prod`, then optional real zones if they exist, then `Node_Cluster 'Managed Kubernetes'`, then workload nodes. If you want to show packaging, use `Node_Container` under the cluster and put `Node_App` inside it; if that is unnecessary, put `Node_App` directly under the cluster. Put `instanceOf` on the deployed application node that represents the logical container, for example `gatewayApp { instanceOf docPlatform.apiGateway }`, `uploadApp { instanceOf docPlatform.uploadService }`, and `workerApp { instanceOf docPlatform.processingWorker }`. If MongoDB is also managed and its host is opaque, model it as an external/managed deployment target such as `Node_SaaS` or `Node_External` instead of inventing a VM.
