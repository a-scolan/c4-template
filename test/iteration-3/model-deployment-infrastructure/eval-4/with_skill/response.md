Add the Prometheus-to-API scrape as a deployment relationship, because that is an infrastructure-specific runtime concern. For example, model Prometheus as its own deployment node and add a scrape edge to the API runtime instance. Keep the API runtime tied back to the logical model with `instanceOf`, so its normal application relationships are inherited. Do not duplicate browser -> API traffic or API -> database traffic in deployment just to visualize them again; those belong in the logical model and flow through automatically to deployed instances via `instanceOf`. In short: add the monitoring scrape in deployment, avoid redrawing normal user/service/data traffic there, and only add other deployment edges when they are true operational exceptions such as backup, bastion access, replication, or log collection.
