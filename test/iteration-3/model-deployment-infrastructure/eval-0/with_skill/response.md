Use the deployment kinds from the shared spec: `Node_Environment`, `Zone`, `Node_Vm`, and `Node_App`. The base shape for production should be `Environment -> Zone -> VM -> Node_App`. For your platform, a clean structure is: `Prod = Node_Environment`, then zones such as `Dmz`, `AppTier`, `ProcTier`, and `DataTier`, then VMs like `ProdApigwVm`, `ProdUploadVm`, `ProdWorkerVm`, and `ProdMongoVm`, and inside each VM a `Node_App` that represents the deployed runtime. Link each runtime to the logical model with `instanceOf`, for example `apiGwApp instanceOf documentPlatform.apiGateway`, `uploadApp instanceOf documentPlatform.uploadService`, `workerApp instanceOf documentPlatform.processingWorker`, and `mongoApp instanceOf documentPlatform.mongoDb`. Add rich Markdown descriptions to every zone and VM: zone descriptions should capture VLAN/CIDR, gateway, firewall, and purpose; VM descriptions should start with `eth0` and then list OS, CPU, RAM, Disk, Port, Monitoring, and RTO. Do not manually copy normal application relationships in deployment. Once a `Node_App` uses `instanceOf`, LikeC4 inherits the logical relationships automatically. Only add deployment-specific edges for infrastructure concerns such as monitoring, backups, bastion access, replication, or explicit operational network hops.
