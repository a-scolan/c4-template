The break is not a mysterious FQN problem; it is a modeling and layout mismatch. `system -> system.api` uses a parent system and its child container as if they were a runtime interaction, but the actual runtime participants in this repo are relationships like `user -> mySystem.webapp` and `mySystem.webapp -> mySystem.api` from `projects/template/system-model.c4`. Then `rank same user, system.api` adds static-view layout syntax that does not match the block-style rank hints used here (`rank source { ... }`, `rank sink { ... }`), and `user` is not even part of your stated dynamic step. Fix the scenario first by using the real interacting elements, then remove `rank same` from the dynamic view or express layout only with supported syntax in a normal view.
