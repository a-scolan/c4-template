Between an app VM and a database VM in deployment, use the deployment taxonomy from `projects/shared/spec-deployment.c4`: `sql` is the better fit when you want a database-specific edge, while `tcp` is valid if you intentionally model only generic transport. Do not use `calls` on the deployment side, because `calls` belongs to the logical-model taxonomy in `projects/shared/spec-global.c4`. In the logical application model, the valid relationship kinds remain `uses`, `calls`, `async`, `reads`, and `writes`; for an app talking to a database, `reads` and `writes` are the most precise, with the protocol recorded in `technology` (for example `SQL` or `PostgreSQL`). To confirm, use `read-project-summary` in a normal workflow and cross-check `projects/shared/spec-deployment.c4` plus `projects/shared/spec-global.c4`; `projects/template/system-model.c4` shows `reads` and `writes` with database technology.
