For deployment between an app VM and a database VM, use `sql` if you mean database queries. Use `tcp` only when you intentionally want a lower-level generic transport connection. Do not use `calls` there: `calls` is a logical/model relationship from `projects/shared/spec-global.c4`, not a deployment relationship. The deployment relationship taxonomy in this workspace is `http`, `https`, `tcp`, `nfs`, `amqp`, `oidc_saml`, `ldap`, `sql`, `redis`, and `smtp` (from `projects/shared/spec-deployment.c4`). In the logical application model, the valid relationship kinds remain `uses`, `calls`, `async`, `reads`, and `writes`; for app-to-database interactions, keep `reads` and `writes`. The workspace guidance in `projects/shared/SPEC_CHEATSHEET.md` is that normal application traffic should usually be modeled in the system model and inherited into deployment through `instanceOf`, so `sql`/`tcp` are deployment-level tools, not replacements for logical `reads`/`writes`.
