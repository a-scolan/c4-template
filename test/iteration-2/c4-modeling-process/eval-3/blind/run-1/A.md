Use this order:

1. **Re-establish workspace context first**
   - project layout, shared specs, valid element/relationship kinds, existing view taxonomy.
   - Skill to call: `understand-project-structure`.

2. **Confirm/refresh C1 boundary**
   - actors, target system, externals, key interfaces.

3. **Design C2 containers**
   - runtime/deployable building blocks and their typed interactions.
   - Skills to call for detail: `create-element`, `create-relationship`, then `design-view`.

4. **Validate coherence**
   - references, kinds, relationships, renderability.
   - Skill to call: `test-model`.

Only after C2 is stable should you consider C3, dynamic, or deployment extensions.
