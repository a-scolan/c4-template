Use this order:

1. **Reconstruct context first**
   - Identify workspace structure, projects, shared specs, naming conventions, and existing C1/C2 views.
2. **Locate the target system boundary**
   - Confirm actors, neighboring systems, and what this new C2 view must answer.
3. **Inventory existing containers/relations**
   - Reuse what already exists; avoid duplicating containers with new names.
4. **Draft the new C2 view purposefully**
   - Include only relevant containers and relationships for the view goal.
5. **Validate consistency**
   - Check terminology, tags, and relation semantics against shared specs.
6. **Refine readability**
   - Adjust layout, grouping, and labels for stakeholder clarity.

Complementary skills to call:

- `understand-project-structure` (first, mandatory for takeover scenarios)
- `design-view` (to shape the C2 narrative)
- `create-relationship` and `create-element` (if model gaps are found)
- `customize-view` (for readability/styling consistency)
- `troubleshoot-errors` (if validation issues appear)
