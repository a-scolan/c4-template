The real cause is the view scope, not `rank same` by itself. `system -> system.api` treats a parent and its child as if they were peers in a dynamic interaction, which is really containment, not a proper scenario step. Then `rank same user, system.api` tries to align an external peer with a nested child, exposing the same hierarchy problem. Fix the view by choosing one abstraction level: either keep it at system level (`user -> system`) or switch to container level and model peer interactions such as `user -> system.webapp` and `system.webapp -> system.api`; use `rank same` only for peers in that chosen level.
