The cleanest LikeC4 approach is usually both, but with strict separation of concerns. Put `SecZone`, `bastion`, `firewall`, and placement/network boundaries only in a Deployment view. Add a C2 only if the new dedicated services are real software containers with responsibilities and interactions that matter at design level. In other words: C2 = logical services and dependencies; Deployment = production topology and security zoning. If `SecZone` is only an infrastructure boundary around already-known containers, Deployment-only is enough; if it introduces new dedicated services, keep those services in C2 and show their placement inside `SecZone` in the Deployment view.
