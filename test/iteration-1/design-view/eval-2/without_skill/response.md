Use a `dynamic view` for the upload journey, backed by the normal static model. Keep the structure in a C2/C3 view, then add one `upload_journey` dynamic view with ordered steps such as `User -> Web App -> Upload API -> Storage -> Scanner -> Notification`. For colors, do not hard-code them per step; tag the critical elements and/or relationships as `critical` or `critical_path` in the model and style those tags in shared or project-level styles. That gives you the right split: static views explain what exists, the dynamic view explains the step-by-step flow, and tag-based styles highlight the critical path consistently.
