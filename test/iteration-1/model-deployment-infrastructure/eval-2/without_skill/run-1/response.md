Do not invent physical hosts you do not actually know. For managed Kubernetes, keep the hierarchy honest: Prod -> managed cluster -> namespace or workload grouping if known -> deployed app instances. Model only the layers you operate or can verify, such as the managed cluster, namespaces, ingress, workloads, and any managed data service. Then wire instanceOf from each deployed app instance to its logical element, for example gateway, upload service, processing worker, and MongoDB. If MongoDB is a managed external service, model it as its own managed deployment node or deployed instance rather than pretending it runs on a VM you cannot see.
