Do not dump everything into one shared bucket. Separate technical conventions from reusable business models, but keep the structure shallow: keep spec files and assets in the existing shared spec area, and add one small shared-domain or common-model area for truly reusable actors and systems. Project-owned models should still live inside each project folder. A good rule is: spec files define language, styles, and conventions; shared domain files define canonical reusable business elements; project folders define local models and views. That avoids both the junk-drawer problem and an over-engineered folder maze.
