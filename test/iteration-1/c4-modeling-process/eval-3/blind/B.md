Approach it in this order:

1. **Re-establish the workspace context first**.
   Confirm the active project, the file layout, the shared specifications in `projects/shared`, and the model/view files that already exist before you design anything new.

2. **Review the current C1 picture**.
   Make sure you understand the system boundary, users, and external systems before touching container design.

3. **Design the C2 view from that context**.
   Identify the main containers, define their responsibilities, and draw only the key relationships needed to explain the architecture.

4. **Use focused follow-up help for detailed work**.
   After the structure is clear, use targeted assistance for:
   - adding or refining elements
   - defining relationships
   - shaping and cleaning up the view

The important rule is not to jump straight into detailed edits. Rebuild context first, then move **C1 → C2**, and use narrower follow-up help for the detailed authoring steps.
