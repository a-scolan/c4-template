Take it in this order: start with `understand-project-structure` to learn the target project, shared specs, and conventions; if the workspace is multi-project or shared, use `organize-multi-project` and/or `configure-project-includes`; then use `lookup-element-kinds` to choose valid kinds; add or refine containers with `create-element`; connect them with `create-relationship`; create the C2 with `design-view`; optionally polish it with `customize-view` and `write-rich-descriptions`; finally run `test-model`, and use `troubleshoot-errors` only if validation fails. The key rule is to understand the workspace before drawing the new view.
