Use a structure-first order: first place the work in the right project and shared-spec setup if the workspace is multi-project; then define the system scope, users, and external systems; then model the C1 context; then model the C2 containers and their main relationships; then decide whether any container truly needs a C3 decomposition; then create the views that expose those structures; then validate the model. Optional steps are C3 for simple containers, deployment/infrastructure modeling, dynamic or sequence views for scenarios, view customization, rich descriptions, and decision records. The rule is to add the next layer only when it answers a real question for the audience.
