Use an element-creation skill first, because this description skill assumes the element already exists. For the processing service, start with `create-element`; for the production VM, use the deployment modeling skill first if you are defining infrastructure. After that, choose format by element type: the service should get a normal prose description, with an optional `metadata {}` block only if fields like owner or regions will be queried. The VM should get a markdown table in its description, with network details first; add matching metadata only if automation needs to query those values.
