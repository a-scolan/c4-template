Keep it operator-first, not exhaustive. Start with a one-line summary, then use a single markdown table with only decision-useful facts. Lead with `eth0` and `eth1` monitoring, then OS, CPU/RAM/GPU/Disk, then runtime or app details, then the few operational fields someone will actually act on, such as health check, restart behavior, and RTO. If a detail will never be filtered, troubleshot, or used during recovery, leave it out. Avoid duplicating tags, relationships, hostname, or zone gateway. Add a `metadata {}` block only for fields your automation or inventory queries.
