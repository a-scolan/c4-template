First learn the repository’s local LikeC4 conventions, not generic UML habits. The real semantic sources of truth are projects/shared/SPEC_CHEATSHEET.md and the shared spec files; .github/skills explains workflow, but it does not define taxonomy, and projects/spec-showcase is for examples, not authority. Key local conventions are PascalCase names, C1 kinds like Actor_Person and System_External, C2 kinds like Container_Api, Container_Queue, and Container_Database, C3 Component, and relationships uses, calls, async, reads, writes. Confirm the active project config before editing. After that preflight, hand off to c4-modeling-process, or to create-element/create-relationship for a narrowly scoped change.
