Once project context is established, the next skill should be c4-modeling-process, because it sequences C1 → C2 → C3 deliberately instead of jumping straight into detail. Before that handoff, this first skill must lock in four things: the active project, the source-of-truth files, the valid local taxonomy, and the real parent boundary you will model under. In this repository that means confirming the project config includes ../shared, then using projects/shared/SPEC_CHEATSHEET.md together with spec-context.c4, spec-containers.c4, spec-components.c4, and spec-global.c4 so later edits do not invent kinds, relationships, tags, or parents.
