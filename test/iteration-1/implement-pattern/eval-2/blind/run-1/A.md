Model Redis as a separate cache concern, not as a replacement for Postgres. If it is just an internal implementation detail, the closest match to the current repository is a cache `Component` inside the API with technology Redis; if it is separately deployed, lift it to its own container. In both cases, keep Postgres as `Container_Database` and preserve the explicit API/persistence -> Postgres read path. Show the API or persistence layer `uses` Redis for lookup and, on a miss, `reads` Postgres and then updates or warms Redis. Avoid a model where the only read path is API -> Redis or where Redis appears to own the database.
