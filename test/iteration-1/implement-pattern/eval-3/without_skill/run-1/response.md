Model Stripe as `System_External` and use two separate relationships: first, your internal `Container_Api` `calls` Stripe over HTTPS to create the payment; second, Stripe separately `calls` your internal webhook endpoint over HTTPS for payment confirmation. If the webhook is just another route on the same API, the second edge can target the same `Container_Api`; if it is isolated, use a dedicated internal API or component for the webhook handler. The key mistake to avoid is drawing the webhook as a return arrow or bidirectional response on the first call, because that incorrectly implies synchronous confirmation.
