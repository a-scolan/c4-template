Use two elements, not two new kinds. If the real payment API is third-party and the mock is internal, model them with existing kinds such as `System_External` for the real provider and `Container_Api` for the internal mock, then distinguish mock vs prod with names, technology, tags, or metadata rather than custom kinds. `create-element` is enough for the element modeling; if you want a reusable convention for mock-vs-prod across the workspace, that is where `implement-pattern` becomes relevant.
