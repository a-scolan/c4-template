Use separate relationships, not one smart relationship. The template already follows this style by modeling `mySystem.api -> mySystem.database` as separate `reads` and `writes`. For cache fallback, do the same: one `reads` from API to Redis, one `reads` from API to PostgreSQL, and add a separate `writes` to Redis only if the API backfills the cache after a miss. Put cache-miss/fallback behavior in the relationship title or description, not in a combined magic edge.
